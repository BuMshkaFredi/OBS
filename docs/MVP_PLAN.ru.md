# План MVP: OBS Voice Assistant

Статус: план до начала реализации. Исходный код, проектный файл и команды ниже ещё не созданы и не проверены.

## 1. Цель MVP

Создать отдельное Windows-приложение в системном трее, которое принимает русские голосовые команды в режиме Push-to-talk через `Caps Lock`, распознаёт их полностью офлайн и управляет OBS Studio 32.2.2 через OBS WebSocket.

MVP должен запускаться после self-contained publish без установленного Python и без обязательного облачного сервиса распознавания.

## 2. Границы MVP

### Входит в MVP

- Windows-only desktop application.
- Работа в системном трее.
- Автозапуск вместе с Windows.
- Push-to-talk: `Caps Lock down -> говорить -> Caps Lock up`.
- Активация по ключевому слову «Бочи» одновременно с Push-to-talk: слово отдельно или перед командой.
- Блокировка обычного переключения состояния Caps Lock.
- Офлайн-распознавание коротких русских команд.
- Управление OBS:
  - начать и остановить запись;
  - начать и остановить стрим;
  - включить Replay Buffer;
  - сохранить повтор;
  - включить и выключить настроенные аудиоисточники;
  - изменять громкость настроенных аудиоисточников.
- Автоматическое включение Replay Buffer после подключения к OBS, если пользователь не выключил его вручную.
- Переподключение к OBS и Twitch после временной недоступности.
- Windows-уведомления об успехе, ошибках и запросах подтверждения.
- Кнопки подтверждения `Подтвердить` и `Отмена`.
- Подтверждение для запуска и остановки стрима, остановки записи, изменения названия и изменения категории Twitch.
- Подключение Twitch через OAuth.
- Изменение названия Twitch после подтверждения с сохранением существующих тегов `!`.
- Поиск точной Twitch-категории, показ найденного результата и изменение категории после подтверждения.
- Пауза настольной Яндекс Музыки при выключении личной музыки и переключение трека голосом.
- Необязательный оверлей числа зрителей поверх всех окон по данным Twitch Helix API.
- MP4-копия записи или повтора рядом с исходным файлом OBS.
- Настройка реальных имён OBS-источников в окне «Настройка OBS»: имена вводятся вручную или подтягиваются из запущенного OBS списком.
- Журнал текущего запуска в памяти без сохранения истории между запусками.
- Ввод названия для файла записи и повтора после завершения записи или сохранения повтора.
- Unit-тесты для parser, dispatcher, confirmation policy и configuration logic.
- Integration/contract tests для границ OBS и Twitch с test doubles.
- Manual test plan для Caps Lock, уведомлений, автозапуска и self-contained publish.

### Не входит в MVP

- Полноценное окно настроек; оно планируется после MVP. Сейчас есть минимальное окно «Настройка OBS»: адрес, пароль и имена источников.
- Редактирование пользовательских команд через UI.
- Переключение сцен.
- Поддержка платформ кроме Twitch.
- Постоянное хранение истории команд.
- Голосовые ответы.
- Облачное распознавание речи.
- Автоматическое неявное сопоставление похожих имён OBS-источников.
- Обязательная GPU-акселерация распознавания.

## 3. Зафиксированные решения

- Язык и runtime: C# 12 и .NET 10.0.12 (SDK 10.0.401), target framework `net10.0-windows`; версии зафиксированы в `.csproj`.
- UI: WPF с системным треем; другой UI-фреймворк не добавлять.
- OBS: OBS Studio 32.2.2, встроенный OBS WebSocket 5.x.
- Speech engine: Vosk 0.3.38 (CPU, офлайн). Решение зафиксировано после benchmark: Whisper на целевой машине давал 28–48 с на сегмент.
- Модель Vosk выбирается по приоритету: `vosk-model-ru-0.42` → `vosk-model-ru-0.22` → `vosk-model-small-ru-0.22`.
- Целевой режим распознавания: CPU обязателен; RTX 5060 может использоваться как оптимизация, но не как требование.
- Платформа: Twitch Helix API и OAuth с минимально необходимыми scopes.
- Секреты: Windows DPAPI или Credential Manager; токены и пароли не хранить в обычном JSON и не логировать.
- Подтверждение: Windows notification с двумя кнопками — `Подтвердить` и `Отмена`; автоматический тайм-аут пока не добавлять.
- Replay Buffer: включать автоматически после успешного подключения к OBS; если пользователь выключил его вручную, не включать повторно до перезапуска приложения; сохранять повтор средствами OBS в стандартную папку OBS.

- Подключение к OBS Studio 32.2.2 через `ws://127.0.0.1:4455` и автоматический запуск Replay Buffer проверены вручную пользователем; параллельные подключения после исправления lifecycle не наблюдались.

### Срез 0. Фиксация проекта и минимальная сборка

Создать solution, WPF-проект, тестовые проекты и базовую структуру директорий из корневого `AGENTS.md`.

Критерии готовности:

- `.csproj` фиксирует точные версии .NET, C# и зависимостей.
- `dotnet restore` и `dotnet build` проходят.
- Приложение запускается в трее с минимальным меню выхода.
- Выбран test framework и добавлен один проходящий тест.
- В `AGENTS.md` обновлены предварительные команды и версии.

### Срез 1. OBS WebSocket и runtime state

Добавить порт OBS, адаптер WebSocket и сервис состояния с retry/reconnect.

Проверить:

- подключение и отключение;
- получение состояния OBS;
- запуск и остановку записи;
- запуск и остановку стрима;
- включение Replay Buffer;
- сохранение Replay Buffer;
- получение списка входов и mute-состояния;
- mute/unmute выбранного входа.

Критерии готовности:

- команда не зависит напрямую от SDK;
- ошибки соединения возвращаются явно;
- после подключения Replay Buffer автоматически включается, но не включается повторно после ручного выключения;
- неправильное или отсутствующее имя источника не приводит к изменению другого источника;
- есть unit tests для dispatcher и adapter test doubles;
- есть manual/integration checks с OBS 32.2.2.

### Срез 2. Caps Lock и захват аудио

Разделить глобальный перехват клавиши и запись аудио на отдельные компоненты.

Критерии готовности:

- нажатие `Caps Lock` начинает запись;
- отпускание `Caps Lock` завершает запись;
- обычное состояние Caps Lock не изменяется;
- повторное или некорректное событие клавиши безопасно обрабатывается;
- пустая или слишком короткая запись не отправляется в распознавание;
- ручной тест подтверждает работу в OBS и в обычном текстовом приложении.

### Срез 3. Офлайн-распознавание и parser

Подключить локальный speech engine, выбрать модель по benchmark и преобразовать текст в строго типизированные intents.

Критерии готовности:

- аудио не покидает компьютер;
- поддерживаются короткие русские команды;
- parser не выполняет действие сам;
- неизвестная или неоднозначная фраза приводит к безопасному уведомлению;
- unit tests покрывают варианты фраз и отрицательные случаи;
- benchmark фиксирует latency после отпускания клавиши и качество на обеих целевых конфигурациях.

Целевой показатель: короткая команда обрабатывается не более чем за 1–1,5 секунды после отпускания клавиши, если это достижимо на конкретном оборудовании.

### Срез 4. Command dispatcher, уведомления и подтверждения

Связать intents с OBS/Twitch ports и добавить Windows notifications.

Критерии готовности:

- безопасные команды выполняются без подтверждения;
- запуск стрима всегда требует подтверждения;
- остановка записи всегда требует подтверждения;
- остановка стрима всегда требует подтверждения;
- изменение названия Twitch всегда требует подтверждения;
- изменение категории Twitch всегда требует подтверждения;
- подтверждение выполняется только после нажатия `Подтвердить`;
- `Отмена` не вызывает внешнюю операцию;
- отсутствие ответа не должно автоматически подтверждать действие;
- результат операции отображается безопасным уведомлением;
- credentials и чувствительные payloads не попадают в лог.

### Срез 5. Twitch

Реализованы Device Code OAuth без client secret, DPAPI-хранилище токенов, Helix adapter,
раздел Twitch в общих настройках и подготовка категории до подтверждения. Подробности:
[`integrations/twitch.md`](integrations/twitch.md).

Автоматические unit-тесты покрывают OAuth/Helix запросы и обработку команд. Ручная проверка
с реальным Twitch-аккаунтом и Windows Toast остаётся эксплуатационной проверкой.

Критерии готовности:

- OAuth scopes согласованы до реализации и минимальны;
- токены сохраняются через Windows DPAPI/Credential Manager;
- приложение проверяет подключение перед изменением метаданных;
- название изменяется только после подтверждения;
- категория сопоставляется с точным `game_id` до подтверждения;
- при временной недоступности выполняется reconnect, а не падение приложения;
- токены не присутствуют в тестах, документации и логах.

### Срез 6. Publish, автозапуск и эксплуатационная проверка

Подготовить self-contained publish и автозапуск приложения.

Критерии готовности:

- приложение запускается на Windows без Python;
- native speech libraries и выбранная модель поставляются явно и проверяются при запуске;
- автозапуск не создаёт несколько экземпляров приложения;
- повторный запуск приводит к фокусировке или использованию существующего экземпляра;
- manual test plan пройден на Ryzen 5 5500H / 16 GB RAM;
- по возможности выполнена проверка на Ryzen 5 3600 / RTX 5060 / 16 GB RAM;
- результаты latency, точности и известные ограничения записаны в `docs/testing/`.

## 5. Минимальный набор команд MVP

| Intent | Примеры фраз | Подтверждение |
| --- | --- | --- |
| `StartRecording` | `начни запись`, `запусти запись` | Нет |
| `StopRecording` | `останови запись`, `выключи запись` | Да |
| `StartStream` | `начни стрим`, `запусти стрим` | Да |
| `StopStream` | `останови стрим`, `заверши стрим` | Да |
| `StartReplayBuffer` | `включи повтор`, `включи буфер повтора` | Нет |
| `SaveReplay` | `сохрани повтор` | Нет |
| `ToggleInput` (микрофон) | `включи микрофон`, `выключи микрофон`, `мут` | Нет |
| `AdjustInputVolume` | `громкость микрофона плюс 10`, `громкость музыки минус 5`, `громкость -5` | Нет |
| `MuteInput` (браузер) | `выключи звук браузера` | Нет |
| `UnmuteInput` (браузер) | `включи звук браузера` | Нет |
| `MuteAllAudio` | `ол мут`, `выключи весь звук`, `заглуши все` | Нет |
| `NextMusicTrack` | `следующий трек`, `переключи трек`, `следующая песня` | Нет |
| `SetStreamTitle` | `измени название стрима на ...` | Да |
| `SetStreamCategory` | `поменяй категорию игры на ...` | Да |

Фактические варианты фраз и названия OBS-источников не должны считаться окончательными до появления панели настроек. Фаззи-сопоставление фразы не должно выбирать OBS-источник: источник берётся только из настроек.

## 6. Обязательные manual test cases

1. Нажать и отпустить Caps Lock без речи: состояние Caps Lock не меняется.
2. Зажать Caps Lock, произнести короткую русскую команду, отпустить: команда распознана и выполнена; `начни запись` показывает уведомление `Запись началась`.
3. Выполнить `останови запись`: без нажатия `Подтвердить` запись не останавливается.
4. Выполнить `останови запись`, затем нажать `Отмена`: запись не останавливается.
5. Проверить подтверждение для запуска стрима, остановки стрима, названия и категории Twitch: без нажатия `Подтвердить` действие не выполняется.
6. Отключить OBS и проверить отсутствие падения, уведомление и повторное подключение.
7. Подключить OBS после старта приложения и проверить автоматическое включение Replay Buffer. **Проверено вручную пользователем: приложение подключилось к OBS Studio 32.2.2 через `127.0.0.1:4455`, Replay Buffer запустился.** Затем выключить Replay Buffer вручную в OBS и убедиться, что приложение не включает его снова, в том числе после переподключения.
8. Указать имя источника микрофона в окне «Настройка OBS» (кнопка «Загрузить из OBS» подтягивает список) и проверить, что переключение изменяет только этот источник и что уведомление показывает фактическое состояние (`Микрофон выключен` / `Микрофон включён`). Короткая команда `мут` делает то же самое. **Без настроенного имени команда не выполняется и пишет понятную ошибку в лог.**
9. Настроить `PersonalMusic` и `StreamMusic` и проверить музыку: `выключи музыку` переключает личную музыку и показывает фактическое состояние, `выключи музыку стрима` / `включи звук стрима` делают явный mute/unmute. `Выключи стрим` по-прежнему останавливает трансляцию, а не музыку.
10. Запустить приложение дважды и убедиться, что не создаются два экземпляра и два глобальных обработчика Caps Lock.
11. Запустить self-contained publish на Windows без Python.
12. Выполнить benchmark распознавания на обеих целевых конфигурациях.
13. Остановить запись и сохранить повтор: появляется окно названия. После ввода `Тест` файл
    получает имя `Тест_<имя OBS>.<ext>`, пустое поле оставляет имя OBS. Проверить то же самое
    при ручной остановке записи и сохранении повтора в самом OBS.
14. Произнести `ол мут`: все аудиоисточники OBS выключаются, видеоисточники без звука не мешают,
    уведомление показывает количество выключенных источников. Убедиться, что стрим и запись
    не останавливаются, а микрофон можно вернуть командой `мут` или `включи микрофон`.
15. Сказать `Бочи` без команды: появляется компактная панель `Слушаю`, затем в течение 6 секунд
    произнести `включи микрофон` — команда выполняется.
16. Сказать `Бочи, начни запись` одной фразой: команда выполняется без отдельного окна ожидания.
17. Произнести команду без ключевого слова, например `включи микрофон`: ничего не выполняется,
    в логе остаётся строка `Без ключевого слова, пропущено`.
18. Зажать Caps Lock и произнести `Бочи, начни запись`: команда выполняется один раз, повторного
    выполнения после отпускания клавиши нет. Окно ожидания «Бочи» после этого закрыто.
19. Сказать `Бочи`, затем сразу зажать Caps Lock и выполнить другую команду: после отпускания
    клавиши фоновая фраза уже не трактуется как команда.
20. Сказать `Бочи, громкость музыки плюс 10`: громкость личной музыки растёт на 10 п.п.,
    уведомление показывает фактическое значение. Повторить `громкость музыки минус 10`.
    Проверить `громкость +10` без цели (микрофон), `громкость браузера минус 5`,
    `громкость музыки стрима плюс 5`, `громкость стрима минус 10` и ограничение на 0% и 100%.
    Отдельно проверить исправление типичных ошибок Vosk: `громкость музыки стрела минус десять`
    и `громкость плюс стал`.
21. Запустить Яндекс Музыку и сказать `выключи музыку`: источник `PersonalMusic` выключается,
    музыка ставится на паузу, уведомление показывает и состояние источника, и результат паузы.
    Затем сказать `включи музыку`: источник включается, музыка остаётся на паузе.
22. Сказать `следующий трек` при запущенной Яндекс Музыке: трек переключается. Повторить
    с закрытой Яндекс Музыкой: команда не падает и уведомляет, что плеер не найден.
23. Остановить запись при включённой MP4-копии: в папке OBS лежат исходный `.mkv` и копия
    `.mp4` с тем же базовым именем, исходный файл не удалён и не переименован. Повторить
    для сохранения повтора.
24. Сменить название стрима, когда в текущем названии есть `!tg` и `!exitlag`: в подтверждении
    видно итоговое название с тегами, после подтверждения теги на месте и не дублируются.
    Затем назвать стрим текстом, который вместе с тегами длиннее 140 символов: команда
    отклоняется, название в Twitch не меняется.
25. Включить оверлей зрителей и запустить стрим: окно показывает число зрителей и обновляется.
    После остановки стрима окно скрывается; позиция окна сохраняется после перезапуска.

## 7. Риски и вопросы до соответствующих этапов

- Точная задержка Vosk зависит от размера модели, длины записи и загрузки CPU; на `vosk-model-small-ru-0.22` измеренный RTF ≈ 0,20–0,23, но крупные модели требуют отдельного замера.
- Перехват Caps Lock и Windows Toast actions требуют ручной проверки на реальной Windows-сессии.
- Версию .NET, speech engine и test framework считать выбранными: .NET 10.0.12, Vosk 0.3.38, xUnit.
- OAuth scopes Twitch нужно согласовать перед реализацией Twitch authorization.
- Формат автозапуска и способ распространения нужно подтвердить перед добавлением installer/startup integration.
- Не добавлять SQLite только ради временной истории: постоянная история в MVP не нужна.
- Яндекс Музыка может не публиковать медиа-сессию Windows или публиковать её под другим
  именем приложения. Тогда нужен запасной вариант (глобальные медиа-клавиши), решение
  принимать по результатам проверки, а не заранее.
- Оверлей зрителей попадает в кадр только если OBS захватывает это окно или весь экран.
  При захвате игры или другого окна счётчик видит стример на своём экране,
  но не зрители трансляции.
- `GET /streams` в Helix отдаёт число зрителей с задержкой и кешированием на стороне Twitch,
  поэтому «реальное время» — приблизительное, с точностью до десятков секунд.
- Теги названия распознаются только по шаблону `!`; теги без `!` не сохраняются, пока не
  появится настраиваемый список.
- Итоговое название с тегами может превысить лимит Twitch в 140 символов; команда отклоняется,
  а не обрезает текст пользователя.

## 8. Definition of Done для MVP

MVP считается готовым, когда:

- все обязательные команды и критерии вертикальных срезов пройдены;
- unit и релевантные integration tests проходят;
- manual test plan для Windows-функций выполнен;
- self-contained publish проверен на Windows без Python;
- OBS и Twitch reconnect проверены при временной недоступности;
- подтверждения не позволяют выполнить опасные действия без кнопки `Подтвердить`;
- offline processing и secret-handling требования соблюдены;
- benchmark speech engine и известные ограничения зафиксированы;
- README, `AGENTS.md` и docs обновлены согласно фактически выбранным версиям и командам.

### 9.1. Управление Яндекс Музыкой

Цель: команда выключения личной музыки ставит на паузу воспроизведение в Яндекс Музыке,
а отдельная команда переключает трек на следующий.

Решения:

- Источник управления — Windows Media Control
  (`GlobalSystemMediaTransportControlsSessionManager`); сессия выбирается по приложению
  Яндекс Музыки, а не по «текущей активной» сессии.
- Новый NuGet-пакет не нужен: проектный TFM `net10.0-windows10.0.22621.0` уже даёт
  WinRT-проекции.
- Если сессия Яндекс Музыки не найдена или приложение не публикует медиа-сессию, команда
  OBS всё равно выполняется, а уведомление отдельно сообщает, что пауза не выполнена.
  Это не ошибка команды и не отменяет переключение источника.
- Управление выносится в отдельный адаптер `Integrations/Media` (`IMediaPlaybackControl`),
  `CommandDispatcher` работает только с интерфейсом.

Работы:

1. Адаптер медиа-сессий: поиск сессии Яндекса по имени приложения, `PauseAsync`,
   `NextTrackAsync`, признак доступности. Вызовы асинхронные, ошибки WinRT обрабатываются
   и не пробрасываются в UI без пояснения.
2. Диспетчер: после успешного выключения `PersonalMusic` вызывать паузу. При включении
   источника пауза не снимается: возобновление остаётся за пользователем.
3. Новый intent `NextMusicTrack`: фразы `следующий трек`, `следующая песня`,
   `переключи трек`, `переключить трек`, `смени трек`, `сменить трек`. Работает через тот же
   `VoiceCommandPipeline`, что и остальные команды; подтверждение не требуется.
4. Уведомление показывает и фактическое состояние источника, и результат паузы
   или переключения трека.

Критерии готовности:

- `выключи музыку` выключает `PersonalMusic` и ставит Яндекс Музыку на паузу;
- `включи музыку` включает источник и не запускает музыку;
- `следующий трек` переключает трек в Яндекс Музыке;
- при отсутствии сессии команды не падают, OBS-часть выполняется, причина видна
  в уведомлении;
- unit tests покрывают выбор сессии, отсутствие сессии и тексты уведомлений;
- ручная проверка с запущенной Яндекс Музыкой.

Статус 27.10.2026: реализовано в `Integrations/Media` и `CommandDispatcher`; unit tests проходят.
Ручные проверки 21–22 требуют настольного приложения Яндекс Музыки и остаются за пользователем.

### 9.2. Запись и повтор: и mkv, и mp4

Пожелание уже реализовано в `Recordings/FfmpegMp4CopyService`: рядом с исходным файлом OBS
создаётся MP4-копия без перекодирования (`-c copy`), исходный файл остаётся на месте.

Задача — закрепить поведение, а не менять его:

- после остановки записи и сохранения повтора существуют оба файла: исходный `.mkv`/`.flv`
  и копия `.mp4` с тем же базовым именем (при совпадении имени — с суффиксом ` (2)`);
- ошибка ffmpeg не удаляет и не переименовывает исходный файл;
- при выключенной настройке копия не создаётся;
- если OBS уже пишет `.mp4`, копия не создаётся;
- manual test 23 подтверждает оба файла на реальной записи.

Кода не требуется, если тесты и документация уже соответствуют. Менять реализацию нужно
только при обнаружении расхождения.

Статус 27.10.2026: уже реализовано в `Recordings/FfmpegMp4CopyService`; изменения кода
не потребовались. Ручная проверка 23 остаётся за пользователем.

### 9.3. Теги в названии Twitch

Цель: при смене названия стрима теги, которые уже есть в текущем названии, сохраняются.

Решения:

- Тег — слово, начинающееся с `!` (`!tg`, `!exitlag`); при сравнении регистр не учитывается.
- Перед подтверждением текущее название читается из Twitch
  (`GET /channels?broadcaster_id=...`). Теги добавляются в конец нового названия
  в порядке появления в старом и без дублей. Если тег уже есть в новом названии,
  он не дублируется.
- В подтверждении показывается итоговое название целиком: пользователь видит,
  что именно уйдёт в Twitch.
- Из названия пользователя удаляется только конечная пунктуация; остальной текст
  и регистр сохраняются.
- Если итог длиннее 140 символов, команда отклоняется с понятным сообщением; текст
  пользователя не обрезается, внешний вызов не выполняется.
- Чтение названия не требует нового scope: используется существующий токен.

Работы:

1. `ITwitchApiClient.GetChannelAsync` (название текущего канала) и тесты разбора ответа.
2. `TwitchTitleComposer` в `Commands` или `Integrations/Twitch`: выделение тегов, склейка,
   проверка длины. Логика детерминированная и покрыта unit tests.
3. `TwitchCommandAdapter.PrepareAsync` для `SetStreamTitle` подставляет итоговое название
   до подтверждения; `ExecuteAsync` отправляет уже проверенное значение.
4. Обновить тексты подтверждения и уведомления.

Критерии готовности:

- теги из старого названия сохраняются, дубли не появляются;
- новое название без тегов получает теги из старого;
- теги, уже присутствующие в новом названии, сохраняют свою позицию;
- итог длиннее 140 символов отклоняется без вызова Twitch;
- ошибка чтения названия отклоняет команду, название не меняется;
- unit tests: извлечение, регистр, дубли, лимит, отсутствие тегов, пустое название.

Статус 27.10.2026: реализовано в `TwitchTitleComposer` и `TwitchCommandAdapter`; unit tests
проходят. Ручная проверка 24 остаётся за пользователем.

### 9.4. Оверлей зрителей

Цель: небольшое окно поверх всех окон показывает число зрителей текущей трансляции.

Решения:

- WPF-окно `Overlay/ViewerCountOverlayWindow`: `Topmost`, без рамки, прозрачный фон,
  не показывается на панели задач и не забирает фокус; положение сохраняется в настройках.
- Данные — Helix `GET /streams?user_id=<broadcaster_id>`; при пустом `data` окно скрывается,
  потому что трансляция не идёт. Новый scope не нужен.
- Оверлей по умолчанию выключен и переключается пунктом трея «Счётчик зрителей»
  с галочкой или флажком в окне настроек. Настройки применяются без перезапуска.
- Опрос идёт только при включённом оверлее и подключённом Twitch; интервал по умолчанию
  30 секунд, минимум 15 секунд, максимум 3600 секунд.
- Сетевые ошибки не показываются уведомлениями: окно сохраняет последнее значение
  и приглушается до 45%, чтобы не спамить во время стрима.
- Оверлей не является частью уведомлений и живёт в модуле `Overlay`; окно не ходит
  в Helix напрямую, данные приходят через порт `IViewerCountProvider`.
- Начальная позиция — правый верхний угол с отступом 24 px; после перетаскивания
  позиция сохраняется и игнорируется, если указывает на отключённый монитор.

Работы:

1. Порт и адаптер: `GetViewerCountAsync` → `(viewers, isLive)`; тесты разбора ответа
   и пустого списка.
2. Служба опроса с отменой, паузой при отключении Twitch и возобновлением после
   переподключения.
3. Окно: число крупным шрифтом, полупрозрачный фон, правильные русские формы склонения
   (`1 зритель`, `2 зрителя`, `5 зрителей`), перетаскивание мышью, сохранение позиции,
   пункт трея «Счётчик зрителей» с галочкой. Показ в OBS — захватом окна или экрана,
   отдельный источник OBS приложение не создаёт.
4. Настройка включения оверлея и интервала в окне настроек.

Критерии готовности:

- на стриме число обновляется без мигания и без перехвата фокуса;
- после конца трансляции окно скрывается;
- перезапуск приложения восстанавливает позицию;
- при недоступном Twitch приложение не падает и не показывает нули как факт;
- unit tests опроса и view model; ручная проверка с реальным стримом.

Статус 27.10.2026: реализовано в `Overlay`, `TwitchViewerCountProvider`, настройках и меню
трея; unit tests проходят. Ручная проверка 25 остаётся за пользователем.
