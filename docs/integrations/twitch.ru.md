# Twitch Integration

## Настройка

1. Создайте приложение на [dev.twitch.tv/console/apps](https://dev.twitch.tv/console/apps).
2. Скопируйте `Client ID` в раздел Twitch окна «Настройки». `Client secret` приложению не нужен.
3. Нажмите «Подключить Twitch», откройте страницу активации и введите показанный код.
4. Подтвердите доступ к единственному запрашиваемому праву `channel:manage:broadcast`.

Client ID сохраняется в `settings.json`: это публичный идентификатор приложения. Access token и
refresh token хранятся отдельно через Windows DPAPI для текущего пользователя. При отключении
локальные токены удаляются; приложение также пытается отозвать access token у Twitch. Секреты
не записываются в лог.

## Команды

- `измени название стрима на ...` — название длиной до 140 символов. Перед подтверждением
  текущее название читается через `GET /helix/channels?broadcaster_id=...`. Слова, начинающиеся
  с `!` (например, `!tg`, `!exitlag`), добавляются в конец нового названия в порядке появления
  в старом и без дублей; при сравнении регистр не учитывается. В подтверждении показывается
  итоговое название целиком. Windows-уведомление требует нажатия «Подтвердить»; только после
  него отправляется `PATCH /helix/channels`. Если итог длиннее 140 символов, команда отклоняется
  до внешнего вызова. Из произнесённого названия удаляется только конечная пунктуация; остальной
  текст и регистр сохраняются.
- `измени категорию стрима на ...` — перед подтверждением выполняется поиск через
  `GET /helix/search/categories`. Используется первый результат; точное найденное название
  отображается в уведомлении, а его `game_id` отправляется только после подтверждения.

Обе команды доступны через общий голосовой pipeline, включая Push-to-talk и ключевое слово
«Бочи». Отказ, закрытие уведомления или отсутствие подтверждения не выполняют внешнее действие.

## Счётчик зрителей

Оверлей зрителей читает `GET /helix/streams?user_id=...`. Пустой массив `data` означает, что
трансляция не идёт: оверлей скрывается. Непустой элемент содержит `viewer_count`, который
показывается в окне поверх всех окон. Используется тот же токен с `channel:manage:broadcast`;
дополнительный scope не нужен.

Опрос идёт только при включённом оверлее и подключённом Twitch. Интервал по умолчанию —
30 секунд; окно настроек принимает 15–3600 секунд. При `401`/`403` опрос приостанавливается
до повторного подключения Twitch; сетевая ошибка не показывается уведомлением, а окно сохраняет
последнее значение приглушённым. Helix кеширует `/streams`, поэтому показанное число может
отставать от реальной аудитории на десятки секунд.

## Сессия и восстановление

Перед Helix-вызовами приложение проверяет access token через `/oauth2/validate`. Близкий к
истечению токен обновляется через Device Grant refresh; при HTTP 401 выполняется одно обновление
и повтор запроса. Twitch выдаёт публичному клиенту сменяемый refresh token, поэтому после
обновления новая пара сразу сохраняется через DPAPI. Если refresh token отозван или истёк,
токены удаляются, а уведомление предлагает подключить Twitch заново.

Для Helix-запросов используется `Client-Id` и `Authorization: Bearer`. Вызовы названия и категории
используют broadcaster ID текущего авторизованного пользователя. На временную сетевую ошибку,
429 или 5xx Helix-запрос повторяется один раз; бесконечного цикла повторов нет.

## Проверки

OAuth и Helix тестируются через подменяемый `HttpMessageHandler`; unit-тестам не нужны реальные
учётные данные или сетевой доступ. Состав названия, разбор числа зрителей, пауза и возобновление
опроса, а также view model оверлея покрыты unit-тестами. Ручная проверка авторизации, изменения
метаданных и оверлея требует настроенного Twitch Client ID и интерактивной сессии Windows.
